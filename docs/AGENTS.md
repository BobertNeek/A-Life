# Documentation

Keep the project intent, current implementation, and measured results distinct.
Use the architecture document for organism/gameplay intent and the current guides
for implementation and operation. Update descriptions affected by code changes;
no dated compliance report, fixed requirement count, or exact wording is required.

Preserve useful recovery instructions and clearly identify the source and limits
of historical measurements. Do not imply that a unit test, screenshot, fixture,
or old hardware run proves current gameplay. Replace completed work orders with
useful operating guidance; Git history retains the process log.
