# CPU joint-membership research V1 (explicit, default off)

`enable_joint_membership2177` is fresh-only and exclusive with terminal-context and trainable-memory-readout research modes. It enables exact-target joint event admission and replaces routed candidate family recall through the existing MemoryContext lanes. The first attention pass and target recall stay ordinary. The existing cap and all learned parameters are unchanged.

The source is the actual shared command outcome with authenticated participation, not isolated action causation. Ambient harm and praise/scold/pet/slap remain part of the genuine shared interval. No event is replayed and no reward is fabricated.

Enabled mode-1 checkpoints use schema8 and an explicit version1 mode field; ordinary checkpoints omit the field and keep their old schema. Enabled collected decisions use a diagnostic-only outer envelope, retaining replay inputs and a separate typed source/work receipt. Ordinary collector/PPO admission rejects enabled rows. These diagnostic replay inputs are not a qualified training dataset or a new learning ABI. GPU and combined research modes are unsupported.

Query work is counted through the existing receipt. Before sealing the motor outcome, a planning pass binds actual executed facts and reserves admission encoding/index work using their size and current record count. This does not construct a hypothetical physiological patch. The reservation includes unused capacity and is deliberately reported separately from actual work, so comparisons must include that cost. The host charges the reservation once in the actual cognitive interval before measuring shared physiology; actual admission must fit or the whole staged host transaction fails without commit. Failure rolls back World, neural, memory and RNG state through the existing host clone transaction.

Bounded CPU tests cover actual execution, cold continuation, rollback, budget admission and mode rejection. A completed 12-life cost-matched pilot found no overall advantage: both routes consumed all four food opportunities, with a postmeal hazard-injury regression in one pair. See [the pilot report](Joint_Membership_CPU_Pilot_2182.md) for exact scope and limitations. No physical superiority, generalization to new object IDs, or action-specific player-feedback learning has been established.

## Additive equal-work comparison (2182)

Fresh CPU comparison modes 2 and 3 share ordinary routed recall, joint-event
query, comparison tariff, capture and admission accounting. Mode 2 applies the
joint family estimate; mode 3 withholds it and uses the already computed ordinary
family fields. There is no second ordinary bank lookup. Both preserve target
recall, cap and actual shared physiology/eligibility.

The comparison reports queried sources separately from applied sources. A
withheld query is not evidence that its estimate reached the neural decision.
Both modes pay the declared logical save/assignment, source-copy and context
re-encoding tariff; this is not a claim of identical machine instruction counts.

All enabled modes are bound into the resident private-authority seal: changing the saved
route while retaining acquired state is rejected. Modes 2/3 persist in schema-7 checkpoints and a separately named collected-row
envelope. Mode 1 uses schema 8; prior unbound schema-6 research checkpoints are rejected by generic restore. Preserve those files and their original qualified executor for historical continuation; this change does not rewrite or automatically migrate acquired state. Ordinary dataset/PPO collectors
remain unsupported and reject enabled rows. These are research-only CPU paths,
not a qualified GPU/game behavior change or a claim of improved learning.

Both fresh enable methods stage and seal a cloned host before committing it. A failed seal leaves the original world, resident state, mode and sampling state unchanged. Ordinary checkpoints and modes 2/3 retain their existing schemas and private-seal calculation.

## Fresh Contact-only candidate (2266)

`enable_joint_membership_contact_comparison2266(founder, apply)` opts a fresh
CPU host into mode 4 (Contact applied) or mode 5 (all replacement withheld).
These modes use checkpoint schema 9 and bind the exact mode in the existing
resident private-authority seal. They cannot be added to an acquired host,
substituted for another saved mode, or silently downgraded to older readers.
Modes 0/1/2/3 retain their previous checkpoint schemas and seal calculation.

Both new modes perform the same one ordinary recall, all-family membership
search, declared comparison tariff, shared-outcome capture and admission work
as modes 2/3. Mode 4 retains joint estimates only for candidates whose declared
action family is Contact. Every other candidate retains the complete ordinary
family value, confidence, source count and best source. Target recall, first
attention pass, existing memory bound, neural learning and biology are unchanged.
No object-kind or chemistry gate is introduced. Applied source receipts contain
only Contact sources; queried-but-withheld sources remain separately visible.
The new live receipt has schema 3 and its comparison names Contact explicitly.

Existing plan-2 collected-row envelopes remain matching-reader roundtrippable;
ordinary PPO/cooperative collector admission still rejects these research rows.
Logical work equality does not imply equal machine instructions or wall time.
Exact untouched-family recall does not imply identical downstream cognitive
projection or neural choices, since Contact input changes can affect the shared
network. This is a source/runtime candidate, not a demonstrated behavioral repair,
a new reward/learner, a checkpoint migration, or a production/GPU selection.


## Contact-query-only comparison (modes 6/7, checkpoint schema 10)

`enable_joint_membership_contact_query_comparison2273(founder, apply)` is a
fresh-only opt-in research construction, never a migration or default. Mode 6
applies Contact membership estimates; mode 7 queries identically but withholds
replacement. Resident authority binds the mode. Existing modes 0–5 retain their
wire, checkpoint, and work contracts. Live receipt schema 4 identifies this query
plan; `comparison.applied_family2266` is Contact in both modes. Queried and applied
source receipts remain distinct.

Unlike modes 4/5, only Contact candidates enter membership lookup/search. Ordinary
recall executes once at the routed recall boundary. Non-Contact family fields and
all target fields remain ordinary. The Contact estimator, eligibility, ranking,
retention, shared bundle outcomes, and support rules are unchanged. In particular,
the second family value is shared mechanical success, not confidence. This plan
introduces no component projection, reward, learner, or genetic change.

All executed membership capture and admission remain unchanged. Logical query
work counts the actual selected index/search/sort/source operations, seven-field
save/construction/assignment for usable Contact estimates, provenance copy, and
one encode/hash when sources exist. Withheld and applied routes do equal work on
identical bank/draft inputs. Empty/no-Contact queries avoid redundant context
encoding and validate only the changed receipt. The metric is logical work, not
machine instructions or wall time. Empty and relevant mixed-family fixtures have lower declared work than modes
4/5; reduction is not universal. A single usable all-Contact candidate can cost
seven more scalar units because this plan explicitly charges construction as
well as save/assignment. This is not a claim of equal work to modes 4/5 or
ordinary routing.

This isolated cost hypothesis is not evidence of a behavioral winner: capture
cost and acquisition-history differences remain, and application can independently
change decisions. No default promotion follows from API correctness tests.

## Opt-in ordinary success-component projection (2275)

Fresh CPU hosts may explicitly select `enable_joint_contact_success_projection2275`
with `apply_projection=true` (mode 8) or false (mode 9). Checkpoint schema 12 and
live receipt schema 6 identify cost revision 2 of this policy; existing modes and acquired states
are not migrated. This is not a default route or a demonstrated behavioral win.

Both modes perform the full all-family membership query, capture/admission, and
Contact application of mode 4. They do not use the reduced-query plan of modes
6/7. One ordinary lookup also retains its original family provenance. Only the
Contact candidate decoder's lane 33 can be replaced with ordinary family success
multiplied by ordinary retrieval confidence. Mode 9 computes the same value but
withholds this one-component projection. Both still report joint Contact recall
as applied. Raw joint values, confidence, sources, cognitive context, other 53
candidate inputs, and all non-Contact decoder rows are unchanged by projection.

Success is shared bundle AND-success, not standalone confidence or per-member
causal credit. Shared valence, danger and energy remain joint estimates; this
policy does not reinterpret them as isolated action rewards. A zero-support
ordinary query projects exact zero with no invented sources: this means no
ordinary success evidence, not an observed member or bundle failure. Raw joint
success and its positive joint provenance remain unchanged. Positive ordinary
success support is retained, rather than universally ablated.

The transient ordinary basis is finalized against its own context and matched
by organism, tick, base frame, bank generation/digest and candidate decision keys.
An explicit receipt reports ordinary raw success/confidence/count/best source,
full ordinary provenance, joint weighted success, projected value, and actual
output. Existing joint source receipts remain separate. Both modes charge the
same declared additional logical copying, validation, provenance and component
selection work, not wall-clock instructions. They are not work-matched to mode 4.

This isolates an application hypothesis from separate query/capture/history
cost effects. It adds no learner, reward, privileged object-kind or chemistry
gate, and does not claim to repair all observed failures. GPU/default behavior is
unchanged. New research rows remain ineligible for ordinary training admission.

The projection's declared work is included exactly once in both the pre-action
ATP affordability accounting and the actual shared cognitive-work interval
charged to physiology. The live query-work receipt includes it once; Core recall
work includes basis preparation but not the CPU projection. Native tests reconcile
these components with the sealed patch and measured biological debit, rather
than testing only applied/withheld work equality.

Pre-publication cost-revision-1 checkpoints (schema 11) remain historical only.
The corrected authority digest seals cost revision 2 separately for modes 8/9.
Both original schema-11 checkpoints and schema-only edits to 12 are rejected;
there is no implicit migration or resealing of those acquired lives. Modes 0–7
retain their previous checkpoint schemas, authority domains and behavior.

for modes 8/9. Historical schema-11 projection states remain rejected. Acquired

not a default or a demonstrated behavioral winner.

## Supported ordinary Ingest outcome projection (2286)

Fresh CPU API `enable_joint_ingest_outcome_projection2286(&trainer,
apply_projection)` selects modes 12/13, checkpoint schema 14 and live receipt
schema 8. Both apply full global joint recall, with comparison.apply=true and no
family mask. Mode 12 replaces only Ingest decoder inputs 32 (valence) and 35
(energy) when the same ordinary lookup has source_count>0, positive aggregate
confidence, and valid owner/profile/family/count/best-source provenance. Mode 13
computes the identical basis and products but withholds projection. Absent
ordinary support retains every joint input unchanged; it is not failure evidence.
Positive support whose weighted value underflows to zero remains eligible. Old
Core-invalid confidence/source tuples remain invalid, not silently repaired.

Raw global joint values/confidence/sources and cognitive context remain intact.
Joint success 33, danger 34, all other 52 decoder inputs, and non-Ingest rows are
not overwritten. Shared joint outcomes still do not identify isolated causal
credit. This is neither a new learner/reward nor an object-kind/chemistry gate,
and does not change defaults or establish a behavioral winner.

Core captures only Ingest's two ordinary raw values, confidence/count/best,
query digest and at most four existing source facts, during the original ordinary
family aggregation. Family-specific cache reuse is preserved. An opaque owned
basis binds organism/tick/profile/base/bank/generation/candidate identities; its
wire evidence cannot be deserialized into an operational basis. No full ordinary
PreparedRecall/frame/receipt is cloned, no second lookup/finalization is made,
and no extra context encoding or hash is requested. Query digest getters copy
already cached four-word identities. Runtime carries the basis transiently and
CPU consumes it by value once.

Fixed logical event tariffs, not measured hardware instructions or physical
words, are reported separately:

- selection: N candidate-family events;
- provenance capture: sum over unique Ingest aggregates of 4+16*S;
- cache copy: sum over actual Ingest provenance cache insert/hit clones of 4+16*S;
- basis construction: 16 + sum over M Ingest rows of 12+4+16*S;
- support validation: sum over M rows of 4+4+16*S;
- CPU transform: 16+N+17*M.

Here M<=N and S<=4. Zero Ingest rows cost exactly 32+2*N additional logical
operations, with no provenance capture. Core includes the complete deterministic
transform cost once in execution_evidence_work. CPU independently counts actual
binding, eligibility, component reads, two products, selections, two assignments
and receipt events, checks equality with the precharged component, and does not
charge again. Both arms execute the products and assignments even when support
is absent. Actual physiology and affordability consume the same complete work
receipt. Failures roll back the atomic step.

The private policy identity binds Ingest, component mask 9, positive ordinary
support, and cost revision 1. Modes 0–11 retain their prior wire/seal/work behavior;
no acquired lives are migrated. The provisional unconditional zero-support
projection was considered but never qualified or used to create new states.
