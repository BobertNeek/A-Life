# Disposable ten-generation sensory-anchor experiment

Apply `bold-anchor-multigen.patch` after `bold-anchor-prototype.patch` only in an isolated research checkout. It adds a test-only-environment mating override: experimental parent assets with identical weight bit patterns and matching layout, route, address and profile metadata are accepted despite different full ABI digests. It does not safely establish general compatibility and must not be enabled in production. The prior patch also changes the V1 sensory encoder under environment control without changing V1 identity; that is explicitly unsafe to ship or use as a genuine V1 save.

One CPU integration test ran a single line for ten successive births. The fixture **manually** generated and attached a child-specific experimental asset each generation after checking indexed synapse coordinates/kinds, carrying all 32,768 inherited starting weight bits exactly. It maintained all 183 baseline sensory-port triples; total ports were 187 in generations 0–1 and 190 in generations 2–9. It wrote and reloaded each composite genetic archive. This was one initial parent pair and one deterministic child per generation, not ten independent lineages or a game reproduction test. No user life, trained checkpoint or optimizer state was touched.

The prototype restores any missing anchor and relocates conflicting new ports; that constrains some gene-driven removals and does not establish that added inputs preserve intended semantics. It does not perform actual gameplay, live GPU checkpoint restoration, a behavioral comparison, or learning. Unequal genetic weight arrays remain rejected in this proof. A production design needs its own self-contained versioned ABI and explicit genetic/recombination semantics, preservation of V1 and existing acquired lives, multi-lineage and negative tests, development and behavior checks, and RTX gameplay validation.
