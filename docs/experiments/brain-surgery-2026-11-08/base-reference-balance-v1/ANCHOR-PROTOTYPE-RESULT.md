# Disposable sensory-anchor prototype

`bold-anchor-prototype.patch` is **research-only**, deliberately relying on process environment variables and a local external anchor file. It changes the V1 encoder without changing V1's identity and therefore is not safe to ship, save as an ordinary V1 result, or merge. It was run only on disposable test data.

In one parent/offspring case, the prototype kept all 183 chosen parent sensory ports, retained four additional child ports, verified matching indexed synapse coordinates and kinds, built a child-bound asset containing the exact 32,768 parental genetic weight bit patterns, and archived and reloaded the child composite genome. The Rust integration test passed on CPU. This is a narrow implementation experiment, not a full inherited-development design, GPU/gameplay test, or proof of learned behavior. It does not solve mating when child-specific asset digests differ, and its rule that restores missing anchors constrains genetic/developmental variation. Extra ports can affect previously established circuits; relocation does not prove functional equivalence. A production approach would require a new, self-contained versioned ABI, explicit genetic semantics, multi-generation breeding, saved-state, behavioral and hardware tests, and must leave existing V1 assets/lives untouched.
