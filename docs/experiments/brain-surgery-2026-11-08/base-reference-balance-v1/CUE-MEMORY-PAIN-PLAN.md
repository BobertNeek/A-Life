# Targeted remembered-pain readout: exploratory weight pilot

The existing episodic candidate memory stores the measured pain-drive change in target-latent lane 2, and CPU decoder input lane 26 carries that value weighted by target confidence. The whole-care founder currently sets all Ingest MemoryContext weights to zero, so the tiny learned memory readout has no reliable useful sign. Test a direct authored weight hypothesis: in a fresh experimental founder, set the existing Ingest MemoryContext lane-26 weights to a shared aggregate gain of -4.0 (evenly distributed over exactly the compiled coordinates, asserting all were zero), retaining Approach70 and all other inherited weights. This biases the neural Ingest score down when the candidate recalls an adverse pain outcome. It adds no new gene, memory system or external action rule; it is an authored prior on existing memory information, and the existing ±0.5 memory clamp remains in force. It could create inappropriate aversions or suppress survival; do not promote based on this pilot.

Use already-observed seed 2026111551, red-safe/red-left, safe-first and harm-first, normal and fast-write sham: four CPU trials. The design uses target pain memory features observed in these cases, so it is explicitly not a held-out test. Preserve actual safe/harm exposures, pain, unforced probe choices, recalled memory input/head terms, exact genetic edits, cold continuation and optimizer checks. If the candidate produces safe choices, this only motivates a new counterbalanced fresh-seed study with cue swaps and unrelated-cue exposure control; fast-write sham isolates synaptic fast writes but not episodic memory learning. A genuine experience effect requires comparing with a history containing the same real outcomes but unrelated training cues. Also test distant/near food, harmless bitter food, and cases where prior pain is unrelated to food before considering gameplay. No GPU or user-life changes.
