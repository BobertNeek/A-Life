# Control test-object spawn order

The first fresh matrix always created red test food before blue. In different-color-history controls every choice was blue, revealing a possible order/identity bias that color and physical-side counterbalancing alone cannot rule out. The new research-only `ALIFE_RESEARCH_PROBE_ORDER` swaps which test food is spawned first while retaining actual red/blue positions and properties. No action, reward, brain or user life is forced or changed. The default red-first setting must reproduce the original case.

Diagnostic pilot: already-used seed 2026111554, red safe, red on left, safe-first, matched history, Approach70 and pain-readout -4; compare red-first vs blue-first under normal and fast-write sham, four CPU trials. Red-first runs must match their original exposure and physical choice traces; blue-first is an intervention on test object order/IDs and is not an independent genotype. Record actual IDs, exposures, choices, restore/optimizer checks, and all censoring. If feasible, add both probe orders to a fresh-seed counterbalanced history/readout/fast-control study; do not call the earlier evidence robust until that control is complete. Existing source chain from CUE-PALETTE-MATRIX-PLAN.md plus `cue-probe-order.patch`; no GPU or production/default changes.
