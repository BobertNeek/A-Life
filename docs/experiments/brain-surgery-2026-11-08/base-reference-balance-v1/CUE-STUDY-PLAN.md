# Real cue-outcome exposure: feasibility pilot

Goal: build toward an experience-required learning test, not another hard-coded skill. Use the existing whole-care experimental brain and native CPU world. Give a disposable fresh creature four sequential single-object exposure opportunities: safe, harmful, safe, harmful, each capped at 64 ordinary neural decisions. Both objects have identical positive primary chemical cue, nutrition, geometry, material, shape and temperature; color is the only exposed feature distinguishing safe and harmful, while the harmful object has real world injury potential. The creature must actually consume each exposure; no forced action or fabricated reward. If any exposure is not consumed within the bound, censor the test rather than invent experience.

After all four actual exposures, introduce red and blue foods simultaneously at matched left/right offsets, both now harmless and equally nutritious. Record first actual consumption, color and whether it corresponds to the previously safe cue; no forced decision. Record physical pain on harmful exposures and cold-next-state/optimizer checks. Initially run one normal pilot, seed 2026111546, red safe, red on left. No claim of learning is possible from that single case. If feasible, run counterbalanced cue mappings and positions with fresh matched seeds and normal vs fast-write sham controls, preserving failures. Beware same genetic/positional innate preferences and correlated exposure order; the counterbalance, actual evidence and control matter. Source is main c3aec16 plus `cue-study.patch` and the two pinned research example support modules. The source includes a local research-only sham switch; never merge it into production. No default or user life is changed and no GPU claim is made.
