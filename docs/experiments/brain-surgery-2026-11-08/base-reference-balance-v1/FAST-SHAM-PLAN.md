# Fresh-life fast-write sham pilot

Research-only local binary; never merge this environment switch into gameplay. The previous detached replay demonstrated small score sensitivity, but did not run an alternate life. The native CPU organism's waking update computes the same candidate fast update and eligibility in both modes; in the sham mode only, an explicit `ALIFE_RESEARCH_FAST_WRITE_SHAM=1` switch suppresses committing those candidate fast writes. Normal mode, phenotype, founder, sensors, world construction, sampler seed and script are the same. This is a causal intervention on fast writes over an entire disposable fresh life, not a change to any user's creature or a migration. Both modes still perform the candidate arithmetic and preserve activity/eligibility and weight-generation bookkeeping; do not claim measured equal wall-clock cost. Other learning/memory/predictor and any sleep mechanisms remain active, so this tests fast-write contribution only, not all learning.

Pilot fresh seed 2026111541, near food and far food, original and two-weight boosted founders, 64 decisions per trial: four normal and four sham trials from the same binary. Compare initial scene and first actual decision/perception, verify normal fast values change and sham remains initial, confirm sham flag and counts, compare actual food consumption and choice sequences, and report all cold-next-step/optimizer checks. Trajectories can diverge because the intervention affects sampling. This simple existing-food scene is not itself a novel-cue learning test. If provenance or safety checks fail, preserve the failure and do not bypass authority. No checkpoints or user data are uploaded.
