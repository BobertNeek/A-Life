## Execution and no-blind-retry contract

The path-scoped workflow is pull_request-only, with no push or manual-dispatch trigger, no matrix and no cache. Integration/static guards run on opened/synchronize/reopened events. The native job is restricted to the initial opened event and run_attempt 1 on the exact head branch experiment/episodic-reader-transfer-20261107, with both base and head repository equal to BobertNeek/A-Life. The orchestrator independently checks those event, repository and branch values, the fixed study identity episodic-reader-transfer-2026-11-07 and the predeclared plan hash. Other future PRs may qualify code but cannot start these lives. This guard does not authorize recreating the dedicated branch or opening a replacement PR; an exact PR-number lock can be added once its number is known. Each life writes a create-new started marker before execution and refuses reuse. It writes its original compact journal/summary privately, then updates the sanitized partial report before starting another case.

If qualification fails before any exposure, a synchronize fixup runs guards only. It does not silently run the replication once CI is fixed. If native work starts and then fails, completed outcomes remain in the sanitized partial report, missing cases remain missing, and exposure_started plus attempted/observed/completed/failed case lists record progress. A valid host_error summary is retained as an observed failed life, not a successful completion. Finalization reconciles independently validated summaries even if execution was interrupted before updating its case list. Static failure-code enums distinguish source verification, core tests, CPU/example tests, build, prepare, runtime case and sanitizer schema without exposing raw error text. Review the outcome before arranging any separately authorized new execution. There is no broad automatic retry, replacement or dose extension.

The prepare-transfer command creates frozen assets and manifests only. transfer-one executes exactly one authorized seed/arm combination. The host orchestrator schedules the fixed eight assignments serially and stops on any command, provenance, reporting or disk failure. Protocol/source checks are independent of behavioral success: a full eight-life run may validly show no learning or grip failure.

## Publication and retrieval

Raw build/runtime logs, journals, assets, fresh diagnostics, checkpoints, neural/optimizer banks and .git stay under runner-private paths and are never uploaded. The only allowed outputs are report.md, summary.json, causal-rows.json, checks.json, build-receipt.json, source-only.patch and SHA256SUMS. The source patch is the declared episode delta; receipts identify the separate reconstruction and full input closure. No binary is uploaded.

An always-run finalizer validates the strict schemas, explicit file allowlist and hashes before the explicit seven-path upload. It never broadens the upload path when a file is missing. Validated summary/check/build receipts and bounded causal rows are also printed between fixed BEGIN_SANITIZED_TRANSFER_/END_SANITIZED_TRANSFER_ sentinels, with SHA256SUMS, so reviewers can inspect results through job logs. No raw log is printed on failure. Oversized causal output remains in its allowlisted artifact with a logged digest.

Static tests use synthetic fixtures only. Hosted tests must still qualify fixed asset admission across all four new bodies, default/mirror configuration, target namespace mapping, identity/restore checks and the reporter's native receipt agreement. If a fixed asset cannot admit a new body, stop and report the constraint rather than regenerating genes.
