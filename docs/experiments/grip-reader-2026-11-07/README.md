## Representation and ordinary execution

`GroundedGripObjectSlotsV1` (profile 4) preserves the old 24 object feature lanes
and ObjectSlots visual/range semantics. A separate digest-bound typed observation
reports only `SelfHeld` or `NotSelfHeld`, using bodily constraint proprioception.
NotSelfHeld does not assert that the object is free: another organism's or the
player's ownership is not exposed through an oracle or menu suppression. The
same Close candidate is offered in those cases and ordinary physical validation
may reject it. No food, injury, hazard, label or target value is consulted here.

The new menu replaces Grab 211 with explicit Close 2201/Contact on NotSelfHeld,
and Release 2202/Other on SelfHeld. Both are Interact/Manipulation and travel
through ordinary factorized selection, joint execution and outcome recording.
Close cannot release. Release cannot acquire on a stale/repeated command. The
world checks actual owner, target existence, player hold, contact and effector.
Release detaches in place using ordinary physical release, with no invented safe
placement search. The legacy ID meanings and legacy Grab behavior remain intact;
new dispatch is gated by the organism's bound grip foundation identity/profile.

Valid carried poses remain in range and are reserved in the existing object and
candidate slot selection, so a held object remains releasable behind gaze,
obstacles and crowding under current ObjectSlots semantics. This is not a new
vision model. A corrupted held pose outside the existing sensing radius is not
qualified as supported proprioceptive continuity.

## Neural route and exact graph changes

`N2048GripReaderCandidateV1` has distinct foundation, compatibility, selector and
recipe identities. It is admitted only with profile 4. Legacy profiles, default
assets and the old selector tags are unchanged; cross-candidate restores reject.

The new memory plan is schema 3: 54 decoder inputs, 4096 memory synapses, gain cap 12.
The complete graph remains 32768 synapses. It does not increase any capacity or
bucket and does not append or reindex physical synapses. Exactly 64 redundant,
initially-zero MemoryContext coordinates change their logical input lane: for
each of eight families, channel 7/source `episodic.start + 55`, eight output rows,
from lane 31 to lane 53. All old memory lanes retain coverage. Physical endpoints,
IDs, receptor/alpha values and other coordinates remain unchanged. This is a new
coordinate graph, not prefix-equal to the old ABI. Schema3's canonical order maps
port 53 back to 31 solely for ordering; CPU and GPU preserve the same accumulation
order. No CognitiveContext plan may coexist with this port.

For validated Close/Release only, family recall uses a private re-encoded query
for the same tracked target's Ingest experiences, with no category fallback.
Stored selected keys and experience records retain the real operation identity.
Ordinary target recall remains. On this new profile only, grip candidates' normal
family lane 32 therefore means Ingest expectation, not simultaneous own-operation
family expectation. Ordinary Contact/Other queries retain their own namespace.

Port 53 receives that acquired family valence multiplied by family confidence.
Unsupported/zero-source malformed contexts reject on the CPU/upload boundary;
valid empty recall produces zero. The GPU also gates the port on schema 3,
profile 4, Interact, operation/family and nonzero source/confidence. Ordinary
Play/Vocal/other actions receive zero. The input is written after cognitive
zero-fill and used by normal scoring, eligibility and gradients. No host
multiplier turns it directly into desirability.

The separate `probe_grip_reader` source constructs inherited genes on this graph.

and eight Other port weights -4 (aggregates +32/-32). Ordinary Other family
weights are not sign-reversed. The source retains the prior target reader and
