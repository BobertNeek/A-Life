# Prepared-memory readout prototype

The optional offline CPU readout lets a destination action use the existing
prepared family-energy expectation of a source action for the same current
tracked target. It adds a separate frozen coefficient term inside the existing
MemoryContext sum, after the legacy terms and before their unchanged cap. It
changes no existing input lane, genetic coefficient, recall ranking or contact
phase rule. In particular, Touch and unknown-phase evidence are retained.

`FrozenMemoryReadoutConstructionV1` is a CPU research configuration containing the
complete unchanged parent genome and a frozen source-family/destination-family
coefficient. It is **outside normal CreatureGenome inheritance** and has no new
Adam, fast-weight or eligibility coordinates. Research founders require an
explicit enable call before their first neural decision. Resume preserves the
configuration; normal reproduction does not inherit this extension. It is not a
new accepted or normally trainable brain.

Source provenance is copied during the existing routed family aggregation. The
binding reads that prepared result, with no additional bank query or whole-bank
export. It requires one matching source candidate with the same entity, tracked
target, owner, frame and profile. Missing, intrinsic, ambiguous or empty sources
produce zero contribution. Prior episode identities remain explicit: native
category recall can generalize from another prior identity, while the current
source and destination must address the same current target. Source first/last
ticks, observation counts, confidence, aggregation weights and contact phases
remain attached. Native retention already affects family confidence; the binding
adds no second age decay and claims no terminal-outcome guarantee.

Enabled CPU checkpoints use schema 5 and seal the full configuration into private
state authority. Readout ABI and work-policy versions are mandatory. Changing a
frozen configuration cannot admit an acquired checkpoint under a different
construction. Default-off fields are omitted, preserving legacy checkpoint and
replay representations. Research rows and readout-bearing candidates use explicit
JSON envelopes, including zero coefficients. Ordinary collector readers and
older paths reject those records. GPU replay rejects readout-bearing candidates;
no matching GPU execution or production admission is implemented.

The prototype charges a versioned logical operation tariff for source metadata,
binding/admission checks, joins, readout arithmetic and bounded validation. It
updates memory-context activity work and cognitive-memory work, and refuses
unaffordable research work before neural advancement. This is not an
instruction-exact energy or hardware-performance measurement; allocator and
ordinary host-validation overhead are not measured. Unaffordable work stops the
atomic host tick; no in-world retry or failed-admission energy model is claimed.
A zero-coefficient enabled
control shares the tariff. A separate default-off control measures the complete
intervention's practical cost.

The existing population example accepts an optional
`prepared_readout_coefficient` while requiring zero legacy weight gain. It keeps
its generic physical fixture recipe. Private requests, acquired states, optimizer
files, executed binaries and trial results are not source deliverables. Enabled
runs retain every step boundary before diagnostic checks. Coefficient-zeroed
replay copies are same-state explanations, not autonomous source-free lives or
retroactive edits to acquired creatures.

Local checks include `cargo test -p alife_training --features cpu-backend --lib
memory_readout_` and `python scripts/test_prepared_memory_readout.py` with CPU
Torch installed. The explicitly ignored historical-checkpoint test requires a
local retained run through `ALIFE_BINDING_LEGACY_RUN`; it performs no world steps.
The independent Torch checker fails if expected tapes or interventions are absent.
A numerical pass does not establish useful choice learning, safety or promotion.
