# Request-contingent language continuation

This opt-in continuation preserves all previous negative results. It remains a
native CPU experiment on disposable public founders. It has not demonstrated
reliable retained language or CFF ChiChi competence.

## Collection and objective findings

The old v3 trace contains two successful toy Grabs from an initially empty hand
in each grounded/shuffled arm, inside EatFood lessons. Its requested-goal filter
discarded these activities for narration. No actual ingestion occurred during
those training rounds. The old action loss also labelled a fixed goal on the
75% of frames without an audible request, allowing word-independent habits.

The v4 collector pairs opposite requests from identical initial native worlds,
uses contact-first physical lessons, and labels actions only while a request is
audible or after a genuine completed activity. The existing native representative
and compatible motor choices are both supervised. Narration follows the actual
activity, regardless of the request. Toy ownership must actually change; food
must actually be consumed. No action, world outcome or biological reward is
manufactured. Quiet behavior is unconstrained. Shuffled control changes request
alignment; truthful activity-narration supervision remains present in both arms.

The v4 comparison restored each arm's real step-64 actor/Adam history and added
64 updates. Grounded collected 24 completed activities and 57 positive narration
rows; shuffled collected 34 and 85. Each has 512 training decisions and 288
scored assessment decisions. Two relocated layouts and a postsleep near layout
each fork the same prepared private state into food, toy and silent requests.
First completed activity is scored against the actual request. A missing first
completion is a failure for a requested trial, even though its raw comparison
field is null. Silent cases have no request-compliance score.

Sleep is explicit native **RecoveryProtocol** sleep, not spontaneous sleep.
One consolidation occurs in the shared postsleep ancestor per arm/assessment
pass; the three cue forks share it. They are not three independent sleep cycles.
Exact cold assessment is repeated for verification. Training uses fresh cohorts
and retained foundation/optimizer state, not a same-individual live optimizer
rebase. Conditional replay retains recorded fast/lifetime offsets and context.

All stages pass exact cold private continuation, next native Adam state, complete
assessment-trace comparison and native recovery-sleep assessment. Across each
stage's nine scored lives, grounded has 5 nourishing meals/13 toy acquisitions;
shuffled has 6/7. Acquisitions can include genuine release/reacquisition; these
are event counts, not independent successful tasks. Grounded has 54 eligible
narration opportunities and shuffled 33, but neither emits speech. Postsleep
request compliance is 1/2 in both arms. No reliable language or sleep-retained
language capability is established.

The grounded actor selects Vocalize 103 times. All 1,024 speech coordinates and
their Adam histories update; empty payloads are the immediate bottleneck. Real
eligible-frame raw presence is about −0.75 to −0.68 after v4. Token bits are
nonzero, but the native presence gate rejects them.

Per-window class balancing leaves only 21.875%/28.125% positive budget in the two
grounded rounds. v5 splits positive/silence native probes and weights them by
their actual corpus mass, restoring global 50/50 budgets. It changes only native
speech coordinates; every other weight, moment and age stays exact. Silence
duplication invariance is tested using native gradients.

Equal class totals still give the shared presence gate nine times more negative
weight: positive rows supervise 18 outputs, silence only two. With identical
inputs, the least-squares presence optimum is −0.64. v6 allocates 18/20 and 2/20
budgets so both classes give each shared gate weight 0.05. A native zero-presence
gradient fixture demonstrates removal of this bias. It changes neither the
decoder threshold nor native backward equations. The same-checkpoint/same-dose
v5/v6 comparisons remain negative. v6 moves sampled eligible presence to roughly
−0.35; 32 further updates also fail to produce utterances.

The saved corpus is retained and checked by SHA-256 for actual stage continuation.
No moments or integer ages are reset. Eight normal tests, strict Clippy and
the real native cold/sleep runs pass. The explicitly invoked real-provider probe

## Remaining sensory limitation

In the actual sparse graph, holding-object tactile lane 34 targets neurons
68/155/215, positive-taste lane 37 targets 137/158/246, and hunger lane 0 targets
256. None reaches speech sources 1856–1887. No homeostasis or proprioceptive
encoder assignment reaches those sources. Some visual/acoustic inputs, ground
contact and aversive taste do reach speech; the world is not wholly disconnected.
This sharply limits direct bodily grounding. More payload updates do not repair
those missing paths. A separate explicit embodied-input experiment must preserve
default/V1 identities and must not migrate accepted or private living state.
The separate [embodied-input experiment](retained-language-embodied-input.md)
implements and measures that restricted fork; its matched result also remains
negative.

## Real provider attempt and resource blocker

No accessible llama.cpp/Ollama runtime, inference Python package or GGUF model
was found in the ordinary installed/model locations. Localhost 18081 refuses
connection. Model-download hosts are not allowlisted. A root-owned cache was
unreadable and was not retried. No network or filesystem guard was changed.

The installed official Codex CLI reports version 0.159.0-alpha.3, supports the
existing Luna adapter's flags, and its ordinary status command reports ChatGPT
login. No credential contents were read or printed. The adapter's three removed
API/base-URL variables were absent, so those removals would be no-ops.

An explicitly invoked probe submits one bounded public simulation observation
through the existing tools-disabled Luna adapter, intended to validate the
provider receipt, actual model output, native semantic context and encoded prior
targets. It fails exit 1: **one request, zero validated replies, zero delivered
frames, zero encoded prior targets, no model output**. The adapter suppresses
stderr; no more specific startup/model-access reason is exposed. There was no
inference retry, alternative routing or credential change. Login readiness does
not establish inference access. [Captured failed attempt](retained-language-luna-provider-attempt.json).

The precise remote blocker is a working authorized execution of that existing
bounded adapter. Local setup additionally requires an authorized compatible GGUF
and the official server binary. The existing translator uses a legacy model
alias; a compatible server command, once those resources exist, is:

```sh
llama-server -m /workspace/models/authorized.gguf \
  --alias alife-qwen3-4b-prior --host 127.0.0.1 --port 18081 -c 4096
```

The alias is a routing name, not proof of model identity or size; record the
actual model and file digest. These flags and CPU inference are supported by
the [official llama.cpp server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md).
For the existing runtime prior, explicitly select `ALIFE_SLM_PRIOR_BACKEND=local`,
the matching `ALIFE_SLM_PRIOR_MODEL`, and its actual SHA-256. None was started or
downloaded here. All measured retained-learning runs above use a scripted teacher.
