# Fresh matched 23xx comparison: protocol and source archive

This source-only archive preserves the disabled pre-execution proposal and a
later active-main-only source delta for the separate matched-world comparison.
It contains no study outputs or executables and makes no behavioral success claim.
It does not claim a publicly timestamped preregistration before study execution.

## Fixed design and interpretation

Two seeds, 2026112301 and 2026112302, each occur in old and new worlds: four lives
and one unchanged inherited asset, identified by SHA-256 in `protocol.json`.
The order is s1 old, s1 new, s2 new, s2 old. Each life receives exactly 600
world-only preparation advances and at most 256 primary steps. Each matched
pair must have identical initial state verified before either member starts.
Stop safeguards are health below 0.70, injury above 0.25, death, or
the third harmful meal. No retry, replacement life, retuning or horizon extension
is part of this protocol.

No weight, scene or teacher changes, forced sleep, or Adam training are allowed.
Ordinary internal plasticity and natural sleep remain part of the inherited
organism. The arms differ by the exact frozen world-factor patch, not by brain
asset or common instrumentation. This tests the bundled world effect. It does
not isolate atomic swap, establish synaptic learning, or demonstrate generalization.
One shared asset across two seed/world pairs is not independent brain replication.
The 1,024 replay ceiling covers explicit detached observer checks, at most one
per primary step. It does not bound ordinary cognition or natural-sleep replay.

## History and limits

The entire earlier 22xx allocation is closed without retry. Its original failed
event and tick remain unknown. Later instrumentation work does not repair that
historical uncertainty. The new seeds were predeclared before the v3 scripted
receipt-fixture outcomes; the written reservation followed the old-arm scripted
v3 result. Freshness is supported only by bounded checks, not a global proof.
No outcome-based seed replacement is part of this design.

Scalar-prefix retention is reporting, not completion: only a strictly validated
contiguous prefix read after confirmed process termination may be admitted.
An incomplete prefix stays partial and comparison-ineligible even at 256 rows.
Requested, returned, projected, collected and admitted counts remain distinct.
Missing or contradictory diagnostics cannot erase verified 600-tick preparation
or admitted rows. Full-case admission retains its separate terminal and byte
receipt checks. Detailed rows are omitted together if necessary to respect the
fixed report cap; summaries and count/hash receipts remain.

## Recovery and boundaries

`source-bindings.json` identifies the source base, common patch, frozen world
factor and reconstructed old/new trees. The world-factor bytes already reside
in `../failed-reserved-attempt/world-factor.patch`; its hash is pinned here.
Apply the common patch to the source base for the disabled old tree and apply
that same common patch plus the exact world factor for the disabled new tree.
The archive commit itself is a documentation snapshot, not either study tree.

Only the exact common source patch, changed reporting/controller source, this
README, the curated protocol and source hash record, and checksums are added. No checkpoints, banks, row payloads,
raw logs, assets, binaries, credentials or private run state are included. Prior
archives remain byte-for-byte unchanged. Native compilation, native tests and
study execution were not performed as part of preparing this archive.

The four changed reporting/controller files are retained byte-for-byte under
`source/`. The unchanged diagnostic and prepared-fixture contracts are referenced
by exact archive path and SHA-256. To inspect the reporting code together, place
the referenced diagnostic contract beside the four retained files in a separate
working directory. This archive is not a self-running controller package: original
plan/metadata files and actual execution bindings are not copied. Snapshot hashes
identify those original metadata files. Generic source-level validation gates
remain intact; no actual activation receipt or private execution binding is stored.

## Later active-source mapping and scalar export bound

Apply `active-main.patch` after the disabled common patch to recover the active
entrypoint. `active-source-bindings.json` pins both resulting arm trees and every
changed source hash. The delta only replaces disabled main with argument parsing
and the existing qualified entry call. Reporting/controller source is unchanged.
This is source identity, not evidence of a compiled executable or a completed run.
Native build and data-only qualification results are not recorded in this archive;
study timing and results must be established separately. Archive publication may
follow study execution and is not asserted to precede it.

`scalar-export-bound.json` records the active-source synthetic scalar calculation:
857,326 mandatory bytes conservatively bounded below the fixed 16,777,216-byte
cap, covering 16 full/prefix assignments and retaining summaries and receipts.
The earlier disabled-source bound was 857,175 bytes; the 151-byte difference is
the active common patch size. This is not a native or behavioral test result.
The exact calculation source and its synthetic `test_contract.py` dependency are
retained under `source/`. Its original relative layout expects a sibling active
package directory and original package manifest; these paths are not a runnable
archive layout. The source/hash mapping preserves the calculation for inspection
without storing actual execution bindings or a self-running dispatch package.
