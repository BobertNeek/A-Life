# Rich-lesson unusable prior cache repair — October 7, 2026

A schema-valid response can contain associations whose saliences are all zero.
The parser preserves these values correctly. Such a response does not satisfy
rich-lesson readiness, which requires a usable receiver-vocabulary association
for the current natural-senses context. Previously, the cache returned this valid
but unusable response forever; setup priming stopped as soon as no request was
pending. Historical delivered frames did not establish current-context readiness.

For rich-required contexts with positive developmental gain, priming now permits
one same-context reconsideration of an unusable cached reply. Feedback explicitly
states that the reply was schema-valid but supplied no usable association. The
provider may return positive salience only for a meaningful context-supported
association and must keep zero if none applies. The receiver never manufactures
associations or salience. A second unusable response still fails admission.
The retry is marked before submission, shares the existing five-second priming
deadline, and preserves the canonical sensed-context key and its 768-character
bound. Ordinary gameplay behavior and the ordinary request prompt are unchanged.

Receipts preserve the original and replacement outputs/digests, exact feedback and
version, and the last priming context, status, developmental gain, cache match,
usable count, pending state, retry use, readiness and exit reason. Prior source
hashes already version the provider identity, so this repair uses a new cache
namespace; original caches and failed receipts remain preserved. This changes
provider retry policy, not the learned foundation or actor/value/Adam format.
Each founder continuation still reconstructs a new world/body/life and retains
the sealed learned parameters and optimizer state.
