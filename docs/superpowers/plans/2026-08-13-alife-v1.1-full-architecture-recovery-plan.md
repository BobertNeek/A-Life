## 1. Outcome

Pass 1 ends with one production architecture in which attention, active concepts, unresolved gaps, prediction, factorized motor control, recurrent and dendritic computation, sparse structural growth, learning, sleep, biology, lifecycle, persistence, presentation, and cognitive economics participate in one causal loop.

The mechanisms may be simple. They may need tuning. They may use temporary compatibility adapters. They may not be stubs, disconnected sidecars, placeholder returns, or TODO-only representations.

The approximate one-day preference supplies urgency, not a stop time. Do not cut a locked capability merely to preserve a small milestone.

## 2. Supervisor and worker protocol

The supervisor owns architecture, integration order, the canonical specification, the compliance matrix, documentation, and protection of unrelated work.

Implementation uses many small Luna Max effort tasks. Each task receives:

- one bounded capability and exact owned files;
- the v1.1 semantic contract it must preserve;
- one focused causal gate;
- a ban on broad Cargo, GPU, corpus, soak, or evidence work;
- a requirement to report the commit and clean status.

After three concrete corrections without acceptable work, a task may move to Sol medium as a last resort.

Every worker uses an isolated worktree based on the current accepted integration commit. The supervisor removes that worktree immediately after its commit is reviewed and merged. Finished worktrees never accumulate.

Workers may edit in parallel only when file ownership does not overlap. Cargo and GPU commands run through one serialized queue. No worker starts a competing build because another worker appears idle.

The protected dirty files at plan creation are:

- `AGENTS.md`
- `crates/alife_game_app/src/production_voxel_renderer.rs`

No task may stage or overwrite them unless the supervisor explicitly assigns that exact file after preserving and reconciling its existing diff.

## 3. Verification budget

For each coherent capability batch:

1. run `cargo fmt --check` only for touched Rust when practical;
2. run one package-level `cargo check` after the batch compiles logically;
3. run one named focused test that proves the capability participates causally;
4. fix failures before merge;
5. do not repeat a successful check unless relevant code changed.

Do not run `cargo test --workspace` during ordinary Pass 1 tasks. Do not run EI corpora, population benchmarks, long GPU tests, soaks, ablations, or release evidence. Use a short physical GPU smoke only when the claim specifically depends on GPU execution.

At the end of Pass 1, run the small named integration set once. Existing relevant tests must remain green, but obsolete tests that only freeze private layouts or source text should be rewritten or removed instead of preserving accidental architecture.
