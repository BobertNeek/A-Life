# Native group-50 training

The training-only `train_n2048_group50` binary admits fifty newborn organisms
immediately. All fifty use the same frozen inherited policy in **one shared
canonical habitat**. Their bodies, chemistry, memory, lifetime/fast weights,
recurrent activation, eligibility, sampled actions and sleep/death state remain
private. Physically separated plots prevent resource competition. Starting resource distance,
direction, variety, hazard/toy arrangements and sampling counters differ; shared ecology can correlate
outcomes. This is not fifty isolated worlds and no exploration speedup is claimed.

The ordinary staged world tick builds one awake memory batch and calls
`tick_memory_batch_training`. Existing WGSL class-arena kernels execute organism
rows in their hardware dispatch dimension (normally two fixed chunks for fifty).
The serial `FoundationTrainingSharedDevice` comparison wrapper is not used.

Build with `cargo build --release -p alife_game_app --features foundation-training
--bin train_n2048_group50`. Run from the qualified checkout:

```text
train_n2048_group50 SOURCE OUTPUT --seed 123 --seed-history history.json --decisions 256
```

`train_n2048_group50 --validate-source SOURCE` performs read-only native source
admission, including both optimizers and phenotype compatibility. It opens no GPU,
allocates no seed, writes no source file, and makes no historical freshness claim.
Use it on the accepted package before training and on a completed group output
after export. Preserve the accepted original and all its directory structure.

`SOURCE` must be a sealed native objective-2 cycle, including any retained critic
correction/terrain receipts, or an accepted `group50.json` continuation. Both
complete actor/value checkpoints and integer Adam ages are restored; neither head
resets. An incomplete history requires `--seed-admission known-exclusions`, which
retains `historical_freshness: unknown`. Strict admission is the default. History
must carry matching immutable policy metadata; known-exclusions requires
`complete: false` and the accepted missing-history/recovery attestation with cited
exact-byte evidence. Admission reuses the merged mixed-care read-only Python
validator for recovery and surviving lane lineage. Python must be available in
the qualified checkout for known-exclusions or an existing mixed-care lane.
Older mixed-care predecessors are rejected; group continuations must retain a
hash-bound ancestry from that lane's latest accepted checkpoint.
History
must bind exact source SHA256s, retain evidence, and import every existing lane
ledger with exact-byte hashes. All reserved/consumed/training seed ranges and
assessment seeds are excluded, including nested allocation receipts. Historical
seed reuse is rejected by this entry point. It cannot be relabelled as fresh.

The group writes an immutable `.group50-seed-N.json` reservation, importable as a
standard Grab exclusion ledger, under the existing lane owner lock before any world or
GPU operation. Failures consume that reservation. Source receipts and history/import
documents are copied into provenance. Do not delete reservations to retry a run.
After a failure choose a new seed and supply updated explicit history. No partial
cohort is accepted as a continuation.

Each organism owns its immutable logical replay stream. GAE does not cross organism
boundaries. Sleep starts a replay segment; real elapsed biological consequences
still contribute to the preceding action. Only confirmed death zeroes bootstrap.
A live truncated life retains a real next decision, excluded from learning loss.
PPO checks every recorded old masked joint probability against the pinned actor
before any updates. Representative-forced slots and temperature come from the
original sampling receipt. Failures remain in learning; successes are never
selected out as a replacement training population or recycled as on-policy PPO.
Each organism's initial capture and each later waking segment also compare GPU
rollout/replay activations, supported logits, EMA and metabolic load with
`abs_error <= 1e-4 + 1e-4 * abs(expected)`.

Replay executes one BPTT graph at a time, normally 256 learning + up to 128 burn-in
rows. `--replay-device-mib` defaults to512 and checks a conservative peak bound (two packed buffer sets during shape changes
plus a dimension-derived bound for persistent objective, accumulation, checkpoint/
readback and bounded critic scratch);
loss windows split when needed while preserving available burn-in.
`--replay-host-mib` defaults to8192 and uses the existing measured process-memory
ceiling. These are replay ceilings in addition to the runtime's admitted arenas;
they do not claim total VRAM occupancy or reserve50 full gradient graphs. An
insufficient budget rejects the run rather than changing organism count/cadence.
The central actor accumulates sample-weighted gradients across50 windows. The
central value Adam fits the accepted full sampled residual on bounded captured
actual-current/next production features across every organism.

`group50.json` separates available on-policy rows, unique rows admitted by accepted
actor updates, and repeated epoch exposures. Valid learning decisions per
collection/total wall second count unique admitted rows, including early KL stops.
It also records
collector row histogram, neural work, runtime inference/learning/traffic counters,
actual adapter/admission, replay allocation, both optimizer update counts, and
per-organism energies, deaths, replay manifests, sealed consumption events and
time to first consumption. Success diversity means distinct organisms/local
starting scenes in one world. Retention and trainer-removed competence remain
Unknown until tested separately. Recorded episode and policy provenance can support
future disclosed retries; no branching/world-model feature is included.

The observability follow-up emits JSON lines to stderr with
`kind: group50_progress`, paired `begin`/`complete` events, a matching `phase_id`,
total `elapsed_seconds` since admitted setup and `phase_seconds` for that call.
Stderr is explicitly flushed. Markers cover initial boundary attachment (which
publishes a base world manifest), exact per-organism capture, snapshot publication, durable rebind,
first tick/capture check, staging, trainer construction, optimizer restoration,
replay writers, collection/boundary verification, actor/value updates, export and
next-cohort rebind. A collector tick phase stays open across no-progress polls
until the world tick advances, avoiding repeated polling messages. An unmatched begin
locates an operation whose return was not observed; it does not prove deadlock or
separate CPU work, driver compilation and GPU waits. These markers add no GPU
polls, warmup decisions, optimizer operations or automatic retry. A timed-out
attempt still consumes its reserved seed and cannot supply a complete handoff.
Progress events count each staged organism row (at most
`50 * (decisions + 1)`), prepared lives out of50, actor windows/passes, and completed
critic updates against their actual planned total. Actor window spans end at the
next loader callback or successful cohort return, including intervening trainer
work; they do not identify individual kernels. Actor Adam age is reported from the
actual return receipt, never inferred from loading a window. Each critic update
reports its actual value Adam age and has its own timed begin/end pair. These
observations add no trainer callbacks, extra GPU readbacks or optimizer actions.

The batch-I/O successor replaces the pre/post per-organism snapshot waits with
`capture_training_states`. One ordered copy submission and map serves all private
rows that fit the measured device limit and a256 MiB staging ceiling, across fixed
class chunks; larger byte totals split staging packets while neural execution
remains batched. Mutable state and cold structural additions remain organism-owned.
Tick labels come from canonical prepared frames; readback adds no world clock.
`training_capture` reports actual successful batches, rows, submissions and bytes.
At50 organisms and16 learning decisions, the ordinary awake case captures17 ticks
(including real bootstrap), hence1700 snapshots. The earlier64-captured-tick example
would mean6400 snapshots;64 learning decisions would normally need65 captured ticks.

Group replay now streams independently compressed, BLAKE3-authenticated records
into `replay/cohort-replay.pending`, retaining private tick, segment, actor/source
and organism identities in a bounded index. Collection progress is **staged**,
not durable. Only completed collection seals the index/footer, flushes and syncs
the bundle once, then exclusively publishes `cohort-replay.bundle`. Unix creation
persists the directory ancestry and publication syncs the containing directory;
Windows uses a non-replacing write-through rename. Ordinary serial row-file writers
retain their prior persistence boundary. The group receipt records cohort sync and
commit counts separately from encoded records. The read-only
`inspect_foundation_cohort_replay` API authenticates a sealed index and every record;
missing publication returns `Uncommitted`, and a corrupt/torn sealed bundle errors.
Pending collection is disposable evidence, never a native continuation. No retry,
seed release or optimizer recovery is inferred from replay recovery. Accepted
founder/Adam packages and immutable consumed-seed reservations remain unchanged.

This addresses future per-tick capture/persistence cost. The120-second PC attempt
only demonstrated initial checkpoint capture: the base tick0 manifest had no GPU
brain references, and tick0 sidecars continued to118.19 seconds. It did not prove
that exact publication, rebind or a first training tick completed. No speedup or
total qualification duration is claimed from source changes or CPU tests.

CPU checks cannot qualify recurrence, sampling, frozen replay ratio, native GPU
checkpoint restoration or group-50 throughput. The current cloud environment has
no GPU. Real adapter qualification must exercise a fifty-row collection and full
update/export/rebind, then compare reasonable numerical tolerance, private-state
isolation and masked action evidence against the established production paths.
No PC workload is authorized by this document.

Architecture trace: AOA-AUTH-001..005 (one canonical organism transaction),
AOA-INV-007/009 (private acquired state and common causal step), AOA-LEARN-002..007
(sealed eligibility and biological credit), AOA-FOUND-004/006 (scene variation and
ordinary lifetimes), AOA-PERF-003/005/006 (bounded replay and measured batching),
AOA-PERSIST-002/004 (native checkpoint continuity). Hardware qualification remains
Blocked; population construction and CPU bookkeeping alone do not certify it.

The ignored hardware test is `group50_gpu` with both `foundation-training,gpu-tests`

`ALIFE_GROUP50_SEED_ADMISSION` defaults to `strict`. The only other accepted value

## Coordinated hardware handoff

The existing PC owner must integrate the published source with source-bound seed
history and current known exclusions before allocating a seed. Reconcile the
already-running `4cca46b4` instrumentation build before any successor build, retaining
its source path, target directory and cache. Do not launch another PC task. With

```text
cargo build --locked --release -p alife_game_app --features foundation-training --bin train_n2048_group50
train_n2048_group50 --validate-source SOURCE
train_n2048_group50 SOURCE NEW_OUTPUT --seed ADMITTED_SEED --seed-history HISTORY --decisions 16 --replay-device-mib 512 --replay-host-mib 8192 --temperature 1

```

The current replay host-memory query requires Windows. With the default Cargo
target directory, the built binary is `target/release/train_n2048_group50.exe`;
use the existing owner's target-directory setting when it differs. Read-only
source validation is also available in the cloud and performs no neural work.

Append `--seed-admission known-exclusions` only when explicitly admitting incomplete
history; its provenance remains freshness unknown. Do not substitute a seed here.
The run must capture fifty first-tick GPU rows, keep fifty episode/replay identities,
report at least fifty successful initial replay comparisons, accept central actor
and value updates, export, and rebind on one native next-cohort decision. Readmission
must preserve the exported integer optimizer steps and checkpoint hashes. Inspect
actual masked sampling/frozen old probabilities, per-life terminal/sleep boundaries,
private state and successful/failed outcomes before claiming qualification.

At sixteen decisions, retained raw value features are about6.64 MiB
(`50 * 17 * 2048 * 4`); replay records, canonical worlds and lifetime contexts are
additional. The N2048 four-microstep 384-row packed graph is about72 MiB before
lifetime contexts; the planner bounds two simultaneous packed sets and auxiliary
scratch under512 MiB, with one active graph. These are estimates/bounds, not observed
whole-process RAM or total VRAM. Runtime collector arena admission is separate and
must be recorded; an8 GiB adapter alone does not establish available capacity.

The host ceiling uses measured process memory plus the next allocation and64 MiB
reserve. Device replay limits are checked before initial trainer construction and
each replay load; window splitting retains up to128 burn-in rows. Insufficient
minimum replay capacity, arena rejection, stalled capture, numerical/ratio mismatch,
device loss or missing optimizer progress fail the run. The owner may terminate
the process on resource pressure; retain its failure/output and seed reservation.
Do not retry the consumed seed, silently reset optimizer state, lower the population
or claim a speedup. Review the failure with the implementation owner before a new
admitted attempt. No wall-time watchdog or external resource monitor is installed
by this mode; those limits remain with the existing PC owner.
